In modern Go (Go Modules era), you can create your projects anywhere you want in your user directory. 
You do not need to place them inside $GOPATH (~/go/src), which was only required in older legacy Go (pre-Go 1.11).

================================================================================

          GIT SSH CLONE TROUBLESHOOTING SUMMARY & COMMAND LOG

================================================================================



1. INCIDENT OVERVIEW

--------------------------------------------------------------------------------

* Initial Error:

    git@github.com: Permission denied (publickey).

    fatal: Could not read from remote repository.

    Please make sure you have the correct access rights and the repository exists.



* Context:

    - Attempted to clone a public repository owned by the user.

    - System: Ubuntu on Linux (WSL / VS Code Terminal).



* Root Cause:

    The VS Code terminal was running under the 'root' user session rather than

    the standard user session ('aditya'). SSH looks for keys and configuration

    in the active user's home directory ($HOME/.ssh). 

    - Keys configured in: /home/aditya/.ssh/

    - Terminal checked:   /root/.ssh/ (no registered keys)



* Final Resolution:

    Switched execution context back from 'root' to the standard user 'aditya',

    allowing Git and SSH to correctly load '/home/aditya/.ssh/id_rsa'.

STEP 4: Identifying Repository & URL Scope

--------------------------------------------------------------------------------

Action Taken:

    Verified repo access parameters (confirmed repo is public, checking why

    a clone could still fail despite successful authentication).



Outcome / Interpretation:

    Public repositories do not require private authorization. The failure

    indicated a disconnect between where 'ssh -Tv' was tested versus where

    the initial clone was attempted.





--------------------------------------------------------------------------------

STEP 5: Root Cause Discovery & Fix

--------------------------------------------------------------------------------

Discovery:

    The terminal in VS Code that ran the original 'git clone' was running as

    the 'root' superuser, while the successful tests were run as user 'aditya'.



Cause Details:

    - Root evaluates: /root/.ssh/

    - Aditya evaluates: /home/aditya/.ssh/

    Because /root/.ssh had no key registered on GitHub, all Git commands run

    from that prompt returned "Permission denied (publickey)".



Fix Applied:

    Exit the root shell or ensure the VS Code terminal profile defaults to:

        user: aditya





================================================================================

3. SUMMARY OF KEY LESSONS

================================================================================

1. SSH keys are strictly user-specific:

   Running commands with 'sudo' or inside a root shell redirects SSH lookup

   to '/root/.ssh/' instead of your normal home directory.



2. Verification commands:

   - Check current user:    whoami

   - Test SSH to GitHub:    ssh -T git@github.com

   - List loaded keys:      ssh-add -l

   - Inspect active paths:  echo $HOME
